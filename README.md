# Minecraft Server Panel

面向飞牛 fnOS 的原生 Minecraft 管理面板，默认访问端口 **4560**。当前第一批实现优先围绕文件管理；前后端共用一个 HTTP 服务。

## 当前实现

- 首次设置管理员、密码哈希、HttpOnly 会话、CSRF 校验和登录限流。
- 接入多个目录，支持只读目录。先在飞牛应用设置授权，再在面板填写实际绝对路径；不自动扫描整台 NAS，也不冒充有已验证的授权目录发现 API。
- 文件/文件夹浏览、面包屑、名称过滤、排序、多选，以及大小、修改时间、权限显示。
- 新建文件或目录、复制和批量删除。自动重命名/移动为避免外部竞争误删数据而禁用；请复制、核对内容，再显式删除原项目。取消接入只解除登记，不删除原文件。
- 多文件与文件夹顺序上传、逐文件进度、单个文件流式下载、文件夹打包下载。文件夹上传保留浏览器提供的相对路径；空目录不会上传。单文件上限 5 GiB，同名文件报错并保留原文件。
- 将单个或多个项目压缩为 `.tar.gz`；解压 `.tar`、`.tar.gz` 和 `.tgz`。归档采用流式处理，不覆盖现有项目。
- UTF-8 文本编辑，上限 2 MiB，保留 CRLF/BOM；保存检查内容版本，冲突时保留编辑草稿并允许重新载入。
- 接入目录边界校验、符号链接路径拒绝、系统与面板目录保护、服务退出时传输取消和修改队列等待。

这里还没有 MC 实例启停、Java 环境登记和实时 MC 控制台。文件管理稳定后再实现这些功能。Java/服务端在线下载不在项目范围内；定时备份、玩家监控和 Docker 不属于当前阶段。

## GitHub 构建

仓库：<https://github.com/JuZiool/MinecraftServer-Panel>

本地仅编写源代码，不安装依赖、不编译或打包。推送 main 或创建 PR 后，GitHub Actions 执行：

1. 安装前后端依赖并进行严格类型检查。
2. 在 Linux 上执行文件边界、编辑冲突、文件夹上传、归档处理和真实 HTTP 认证测试。
3. 编译前端与后端。
4. 下载本次云端使用的精确 Node 24 补丁版本，并校验官方 SHA-256。
5. 组合原生程序，检查启动、健康接口、静态页面、状态及停止流程。
6. 上传 `native-preview-linux-x64.tar.gz`、构建信息和云端生成的依赖锁文件。

工作流：`.github/workflows/build.yml`。初始代码尚未推送，也尚未执行云端验证。没有锁文件时首次使用 npm install；Actions 会上传生成的 package-lock.json，验证通过后可将该锁文件加入仓库并切换到 npm ci。

## FPK 状态

`fpk/` 是原生适配草案，**尚未核实平台规范，尚未产生可安装 FPK**。目前默认云端产物是原生预览包。

阻塞真实 FPK 的具体事项：官方 manifest / privilege / 桌面入口格式，目录授权的 resource 声明，平台持久化目录环境变量和启停约定，以及固定 fnpack 下载地址和摘要。特别是 `fpk/config/resource` 当前为空，构建脚本会拒绝用它生成 FPK，避免把未接入文件夹授权的包当作完成品。

补齐并核实后，在 GitHub 仓库 Variables 设置：

- `FNPACK_URL`：固定版本的官方 Linux amd64 可执行文件 HTTPS 地址。
- `FNPACK_SHA256`：对应文件的 64 位 SHA-256。

手动运行 Actions 时选择 `build_fpk`。工具摘要校验失败、模板仍空或工具未输出 FPK 时任务失败，不会上传伪装的安装包。详细待核实项见 `fpk/README.md`。Linux 生命周期检查不能替代飞牛真机的目录授权、应用启动/停止、桌面入口及升级保留验证。

## 程序配置

| 环境变量 | 用途 |
| --- | --- |
| `SERVER_PORT` | 默认 4560 |
| `PANEL_HOST` | 默认 0.0.0.0 |
| `PANEL_DATA_DIR` | 管理员和目录配置的独立持久化目录 |
| `PANEL_PUBLIC_DIR` | 编译后的前端资源目录 |
| `PANEL_APP_DIR` | 生命周期脚本使用的原生程序目录 |

原生程序以应用账号运行，安装包自带 Node，用户目录的权限交由飞牛管理。程序不递归 chmod/chown 授权目录。管理员配置和接入目录信息位于持久化目录中，不通过 Web 静态目录提供。

## 文件操作边界

- 符号链接和设备等特殊文件显示在列表中，但不支持打开或选择操作。
- 过滤只作用于当前目录；当前版本不做全文检索。浏览器文件夹上传会保留文件相对路径，但浏览器不会提供空目录。
- 压缩输出统一为 `.tar.gz`；解压支持 `.tar`、`.tar.gz`、`.tgz`，最多 200000 个条目、解压后 100 GiB。绝对路径、父目录跳转、反斜杠路径、符号链接、硬链接及特殊文件会被拒绝。
- 归档先写入同一文件系统的临时文件或目录，验证后再发布；目标顶层名称冲突时停止且不覆盖已有内容。批量发布期间发生外部文件系统竞争时，已发布项目不保证回滚。
- 自动重命名和移动返回明确提示：先复制，核对后删除；在没有安全的条件删除文件系统原语时，不用“先检查再删除”冒充原子操作。
- 批量操作串行执行，发生错误时部分项目可能已完成；前端会刷新真实列表，不保证整批回滚。
- 原子文本保存保留基本权限位，替换文件的属主为应用账号，ACL 继承父目录；飞牛真机验收需要确认原 NAS 用户仍可访问这些文件，不宣称保留全部原文件 ACL。
- 面板串行化自己的修改请求；NAS 上其他程序可以同时修改文件，文本编辑通过版本检查发现冲突，但本程序不是隔离不可信系统进程的沙箱。
- 删除需要确认且永久删除，当前不提供回收站。请在确认框核对项目。

## 目录

- `client/`：React / TypeScript / Vite / Tailwind 文件管理界面。
- `server/`：Express / Node 标准库后端及 Linux 云端测试。
- `fpk/`：待平台核实的原生包模板和生命周期脚本。
- `scripts/`：GitHub 原生组合、摘要检查、生命周期检查及条件 FPK 打包。
- `参考项目/`：仅本地参考，已排除出本项目 Git 提交。
