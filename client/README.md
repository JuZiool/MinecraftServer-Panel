# Minecraft 文件管理界面

React 19 + TypeScript + Vite 6 + Tailwind CSS 4 的中文本机文件管理客户端。生产构建输出为 `client/dist`，由后端在端口 `4560` 提供静态文件；开发模式的 `/api` 请求代理到 `http://127.0.0.1:4560`。

## 工作区脚本

包名为 `@mc-panel/client`。在 GitHub Actions 中通过根工作区执行：

```sh
npm run check --workspace @mc-panel/client
npm run build --workspace @mc-panel/client
```

本次交付只进行了源码审阅，没有在本地安装依赖、运行应用、构建或测试。

## 接口约定

- JSON 成功响应直接返回对象；错误读取 `{ error, code? }`。认证使用同源 HttpOnly cookie，写请求发送 `X-CSRF-Token`。
- `path` 是 POSIX 格式的根目录相对路径，根目录使用空字符串；注册目录的 `path` 是服务器本机的绝对路径。
- UTF-8 读取返回 `{ content, revision }`，保存携带原 revision；HTTP 409 会读取最新版本并保留本地内容，让用户选择载入服务器内容或保留本地内容后重新保存。草稿可下载；关闭未保存文件需要明确确认。
- 后端负责绝对路径验证、目录边界、只读限制、符号链接限制、有效 UTF-8 与二进制拒绝，以及 2 MiB 文本、5 GiB 上传限制。前端也会拦截明显非法名称和超限内容。
- 上传为顺序 XHR PUT，原始 `File` 请求体，`application/octet-stream`，逐文件进度。文件夹选择使用浏览器的 `webkitRelativePath` 并允许后端逐级创建父目录；空目录不会出现在浏览器文件列表中。重名 409 展示为失败，原文件由后端保留。
- 单文件下载和文件夹 `.tar.gz` 打包下载先检查当前会话，再使用带 cookie 的原生链接；内容不会在浏览器中整体缓存。下载流本身由浏览器接管，流开始后的 HTTP / 网络错误由浏览器处理。
- 所选项目可压缩为 `.tar.gz`；`.tar`、`.tar.gz` 和 `.tgz` 可解压到当前目录。归档冲突、安全校验和资源限制由后端强制执行。
- 任何文件写操作结束后都刷新列表，包括错误和部分失败。取消目录注册只移除入口，不删除磁盘文件。符号链接与特殊文件仅展示，无法选择或操作。

## 联调验收场景

1. 首次 setup、登录失败、成功登录、退出、接口 401 后重新登录；检查所有认证写请求的 CSRF 头。
2. 注册可写、只读和不可用目录；验证不可用错误可见，取消注册不会删除实际文件。
3. 浏览根目录和嵌套目录；本层搜索、排序、多选、新建及跨目录 / 跨注册根复制。重命名和移动使用复制、核对、手动删除流程。
4. 对已存在名称执行创建、粘贴和上传；验证冲突报错且原项目保留。确认界面不提供自动重命名/移动，后端直接收到这类请求时返回 409 并提示复制后显式删除。
5. 删除多个项目并模拟部分失败；验证再次操作前看到真实剩余项目和 API 错误码。
6. 保存文本、外部修改触发 revision 冲突、保留或替换编辑内容、下载本地草稿、取消未保存关闭；验证只读 / 二进制 / 超 2 MiB 文件的处理。
7. 上传多个文件、包含嵌套层级的文件夹、空文件、同名文件、超过 5 GiB 文件及连接失败；验证相对路径、每个文件状态、进度与实际目录结果，确认空目录不会上传。
8. 压缩单个文件、文件夹和多选项目；解压 `.tar`、`.tar.gz`、`.tgz`，验证同名顶层项目不被覆盖，链接或越界条目被拒绝；验证文件夹下载得到 `.tar.gz` 流。
9. 使用键盘操作对话框、窄屏浏览与选择；验证下载使用 cookie 和附件流。
