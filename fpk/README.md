# 飞牛原生 FPK 适配状态

本目录是原生安装包适配草案，不使用 Docker。应用应以专用应用账号运行，默认端口为 4560；Node.js 随安装包提供，用户的 Java 和服务端文件留在已授权的 NAS 目录中。

## 当前待核实项

当前环境无法读取飞牛官方开发文档，尚未核实 manifest、privilege、resource、桌面入口、持久化目录环境变量以及 cmd/main 的状态退出码。这里的模板不能视为已通过飞牛验收的安装包。

特别是：`config/resource` 的目录授权声明仍未填写。不得通过 root 运行、chmod 777 或扫描整台 NAS 绕过授权。需要按官方当前规范补齐“应用设置 → 文件夹授权”，再在面板中登记实际绝对路径。面板只操作登记目录，访问仍由应用账号的系统权限决定。

## GitHub 构建

普通推送执行类型检查、真实 HTTP/文件测试和前后端编译，生成原生应用预览产物。手动选择 FPK 构建前，应先核实本目录中的模板，并在仓库变量中设置 `FNPACK_URL` 与 `FNPACK_SHA256`（官方 Linux amd64 可执行文件的固定下载地址及 SHA-256）。不使用未知版本的猜测地址，也不在校验失败后继续打包。

构建脚本调用 `fnpack build`；该命令与模板需要首次云端运行进一步确认，成功打包仍需飞牛真机安装、文件夹授权、应用启停和升级测试。当前尚未生成或发布 FPK。

## 环境

生命周期脚本优先使用明确传入的 `PANEL_APP_DIR` / `PANEL_DATA_DIR`；`TRIM_APPDEST` / `TRIM_PKGVAR` 是等待确认的飞牛环境变量候选。配置和日志与只读程序目录分离。升级保留数据的行为需要真机验证；卸载保留策略也应在官方安装流程中确认，不能假定平台自动保留所有数据。
